How I build with Claude

The solution design is mine. I map the manual process and sketch how to fix it before Claude sees it. Then Claude becomes my sparring partner: I ask it to check feasibility and to break my design, so the weak spots show up before the code does.

map the manual process→design my solution→Claude stress-tests it→fit the pieces together→write & diagnose the code→refine in real use

Inside the tools, Claude does the judgment work: summarizing emails into a fixed structure, and choosing next steps from a curated library instead of inventing them.

Design principles

Day-one answer, then iterateI get to a working prototype fast and improve it through real use, instead of spending months chasing a perfect answer on paper.
One click before fully automaticA person approves until the output has earned trust. Then the human step can go.
Validate and log every writeBad rows are rejected with a reason; every push to another system is timestamped.
Build the data layer onceOne clean extraction feeds everything, so new reports need formulas, not new integrations.
Libraries over hard-codingStandard steps live in an editable library anyone can extend, so tribal knowledge becomes a shared playbook.

What gets me going

My rule is simple: the first time, I do it by hand. The second time, especially if it's mind-numbingly manual, I'm already sketching how to automate it. There is no third time. Long before AI, when I started in data analysis, I noticed we ran the same analyses for client after client. So I built Excel templates: paste the data into the right columns and the tabs worked out the results on their own, turning hours of repeat work into under 30 minutes.

Then I pushed the idea further. I added a reference table that maps where every kind of data belongs, so the template could handle any data transformation: a few dropdown selections, and the analysis was done. Claude has just raised the ceiling on what I can build.

I'm proud of everything I've built, but the part I love most is the building itself. When someone tells me one of my tools gave them their time back, that's what makes me want to build the next one.
